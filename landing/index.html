What is Chakram

A New Kind of
EVM Blockchain

Chakram is a Layer 1 blockchain that cleanly separates consensus from execution. CometBFT v0.40 handles validator coordination and instant BFT finality; go-ethereum v1.17 handles smart contracts and EVM execution.

Once a block is committed by >⅔ of active validators, it is final — forever. No probabilistic finality, no long confirmation waits, no chain reorgs. Your transactions are either in or out, within seconds.

How Chakram Works

A clean separation between consensus and execution gives Chakram both the security of BFT finality and the flexibility of a full EVM.

Consensus

CometBFT v0.40 runs PBFT-style BFT rounds. >⅔ of active validators must sign a block before it's committed. One missed round → timeout, next proposer takes over. Currently equal voting power per validator.

Execution

go-ethereum v1.17 processes every EVM transaction identically to Ethereum. The same opcodes, same precompiles, same gas rules — just different consensus underneath.

Engine API

CometBFT talks to geth via the same Engine API that Ethereum uses: engine_forkchoiceUpdatedV3 + engine_newPayloadV3. JWT-authenticated over localhost.

Staking Registry

A Solidity smart contract on-chain governs the entire validator lifecycle: registration, stake management, reward routing, and slashing — fully transparent and verifiable.

Why Chakram

Built for Real Apps

⚡

Sub-Second Block Times

CometBFT's timeout-driven rounds produce blocks in ~1 second under normal conditions — fast enough for real-time applications.

🔒

BFT Finality

Once committed, a block cannot be reversed. No waiting for 12 or 32 confirmation blocks. Your users see instant settlement.

🛠️

EVM Drop-In

Use every Ethereum tool you already know — Hardhat, Foundry, Remix, MetaMask, OpenZeppelin. Zero friction deployment.

📜

Validator Set Governance

Stake-weighted on-chain vote to open the validator set to permissionless entry — 66% quorum, 7-day voting window, 30-day cooldown between proposals.

🌐

Permissionless Transition

The validator set opens permissionlessly once any of three triggers fires: 548 days elapsed, 20 active validators reached, or a 66% governance vote passes.

📊

Slashing & Jailing

Misbehaving validators are slashed and jailed by the ABCI layer. A configurable percentage of stake is burned or sent to treasury; jailed validators must unjail to re-enter.

💎

Delegation Registry (Planned)

A future DelegationRegistry contract will let CHK holders delegate to validators and earn commission-adjusted rewards. Commission rates (0–100%) are already stored on-chain.

🔑

Validator Metadata

Each validator registers a name (up to 64 chars), website (up to 128 chars), and commission rate on-chain — readable by any smart contract or front-end.

🔄

No Reorgs, Ever

PBFT-style BFT consensus means the chain never forks after block finalization. Applications can trust the first confirmation.

Run a Node

Become a Validator

A single binary — no Docker, no installer. Works on Windows, Mac, Linux, or any VPS.

1

Download chakram-node

One file, no installer. Pick your platform:

🐧 Linux (amd64) 🍎 macOS (Apple Silicon) 🪟 Windows (x64)
2

Run it

# Linux / macOS chmod +x chakram-node && ./chakram-node
# Windows (PowerShell) .\chakram-node.exe

On first run it downloads geth, fetches genesis from the network, generates your validator keys, and opens the dashboard at localhost:8080 — fully automatic.

3

Register as a validator

Once synced, open the Staking tab at localhost:8080, stake CHK, and register. Your node starts earning block rewards immediately.

Requirements

  • Windows 10+, macOS 11+, or Linux
  • 4 GB RAM · 50 GB free disk
  • Ports 26656 & 30303 open (inbound) for servers
  • CHK to stake (not required just to sync)

Commands

./chakram-nodeStart
./chakram-node statusHeight + peers
./chakram-node stopGraceful shutdown

Running 24/7 on a server?

Drop the Linux binary on any VPS (GCP, Hetzner, DigitalOcean, etc.) and run it as a systemd service — same binary, no Docker required.
